# Handoff: Fitbaza — тренировка у клиента (мобильное приложение)

## Overview
Клиентская часть: тренер собрал тренировку в веб-конструкторе, клиент открывает её в мобильном приложении. Три экрана одного сценария: **план дня → выполнение подхода → итог и отчёт тренеру**. Дизайн — та же система, что и у конструктора (палитра, шрифты, пилюли, скруглённые карточки).

## About the Design Files
Файлы в этом бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие задуманный вид и поведение, **а не продакшн-код для копирования**. Задача — **воспроизвести дизайн в существующем окружении целевого приложения** (SwiftUI / Compose / React Native / Flutter — по стеку проекта), используя его паттерны и компоненты. Если стека ещё нет — выбрать подходящий и реализовать там.

Технически `.dc.html` — самодостаточный HTML; разметка лежит внутри тега `<x-dc>`, стили инлайновые, `support.js` — только рантайм превью и в продакшн не переносится. Рамки телефонов и подписи «01 · ПЛАН ДНЯ» — это презентационная обёртка макета, **не часть UI**.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы и радиусы финальные. Интерактив не запрограммирован — каждый экран показан в одном состоянии, поведение описано словами ниже.

## Device & frame
- Логический размер экрана: **390 × 844** (iPhone 14 / 13). В макете вокруг — бутафорская рамка (`border-radius: 46px`, `padding: 10px`), её не реализовывать.
- Внутренний контейнер: фон `#F6F6F2`, layout `grid-template-rows: auto 1fr auto` — **шапка / скролл-контент / нижняя панель действия**.
- Шапка и нижняя панель — белые (`#FFFFFF`), с внутренним скруглением к контенту: шапка `border-radius: 0 0 26px 26px`, нижняя панель `26px 26px 0 0`. Контент между ними — `padding: 12px`, вертикальный список карточек с `gap: 10px`.
- Статус-бар в макете нарисован (время 11px Mono/600 + две фигурки-индикатора) — в приложении использовать системный.
- Home-indicator: полоса 120 × 4, `border-radius: 999px`, `#D2D2C9`, `margin: 10px auto 0`.

## Interactions & Behavior
- **Старт**: «Начать тренировку» → экран 2 на первом невыполненном упражнении; запускается таймер сессии (мета в шапке).
- **Чекбоксы (экран 1)**: тап отмечает упражнение выполненным — круг заливается `#D6F84C` с галочкой `#4E5C15`, строка получает фон `#F1F5DF`, текст без изменений (не зачёркивать).
- **Подход (экран 2)**: «Подход выполнен» → текущая пилюля в ряду становится тёмной с галочкой, следующая — активной (белая с чёрной рамкой), автоматически стартует таймер отдыха. По окончании подходов — переход к следующему упражнению с плавной сменой заголовка.
- **Вес**: «+» / «−» меняют вес шагом 2.5 кг; long-press — ускоренный повтор; тап по числу открывает numpad. Изменённый вес относительно плана помечать (например, чип «≠ плана») и передавать тренеру в отчёте.
- **Таймер отдыха**: отсчёт вниз, «+30» добавляет 30 с, тап по значению — пауза; по нулю — тактильный отклик + звук, карточка кратко подсвечивается `#D6F84C`.
- **Видео**: тап по плейсхолдеру → полноэкранный плеер с техникой; загрузка — тот же `#E4E4DC` со скелетоном.
- **Свайпы**: горизонтальный свайп по экрану 2 листает упражнения блока; свайп вниз по шапке — свернуть в список (экран 1).
- **Завершение**: после последнего упражнения — экран 3; тактильный отклик; счёт «12 из 12» и рекорды считаются на клиенте, отправляются одним отчётом.
- **«Отправить тренеру»**: PATCH отчёта (факт по каждому упражнению, оценка сложности, комментарий) → успех показывать сменой кнопки на состояние «Отправлено» (фон `#D6F84C`, текст `#111110`) без ухода с экрана; при офлайне — очередь и повтор.
- **Состояния**: pressed — `scale: 0.98` + затемнение фона на ~4%; disabled — `opacity: 0.4`; загрузка внутри кнопки — точечный индикатор `#D6F84C`; ошибка отправки — тёмная карточка-тост `#111110` с текстом `#F6F6F2`.
- Переходы между экранами: push слева-направо 260 ms, `cubic-bezier(0.2, 0, 0, 1)`; карточки контента появляются со сдвигом 8px и fade 180 ms со шагом 30 ms.
- Прогресс сессии сохраняется локально: при выходе через «✕» — подтверждение «Продолжить позже / Завершить», при возврате восстанавливать позицию и таймеры.

## State Management
- `session`: `{ workoutId, startedAt, elapsedSec, status: 'planned' | 'active' | 'finished' | 'sent', currentBlockIndex, currentExerciseIndex, currentSetIndex }`
- `workout`: `{ date, title, blocksTotal, exercisesTotal, estimatedMin, coachMessage, blocks: Block[] }`
- `Block`: `{ id, title, type, restSeconds, note, exercises: Exercise[] }`
- `Exercise`: `{ id, nameRu, nameEn, equipment, videoUrl, planned: { sets, reps, percentOf1RM, weightKg, durationSec, calories }, actual: Set[] }`, `Set: { reps, weightKg, done, changedFromPlan }`
- `restTimer`: `{ totalSec, remainingSec, running }`
- `report`: `{ difficulty: 'easy' | 'onPoint' | 'hard' | null, comment, records: Record[], sentAt }`
- Производные: строка прогресса шапки, флаги «выполнено», тоннаж (`Σ reps × weightKg`), количество рекордов (сравнение с историей 1ПМ), «следующее упражнение».
- Данные: тренировка приходит от тренера (read-only план); клиент пишет только `actual` и `report`. Нужен офлайн-кэш текущего дня + очередь отправки.

- **Нужны реальные ассеты**: видео/превью техники упражнений (экран 2, блок 168px) — берутся из базы упражнений.
