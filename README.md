# Тренерграм — приложение для тренеров

Внутренняя документация по разработке приложения для ведения тренировок: для тренеров по кроссфиту, тренажёрному залу и смежным видам спорта.

Репозиторий — единый источник требований для разработчика и дизайнера. Все идеи и заметки основателя собраны, структурированы и приоритизированы здесь.

## Две ветки, одна публикация

Репозиторий разделён на две параллельные ветки. Обе публикуются на GitHub Pages, каждая по своему адресу:

| Ветка | Что в ней | Адрес |
|---|---|---|
| **`main`** | Документация продукта: `docs/`, `mkdocs.yml` | <https://serjnsk.github.io/trenergram/docs/> |
| **`prototypes`** | Кликабельный прототип MVP: `mvp/` | <https://serjnsk.github.io/trenergram/prototype/> |

В корне — заглавная страница со ссылками на оба раздела: <https://serjnsk.github.io/trenergram/>

GitHub Pages даёт один сайт на репозиторий, поэтому обе ветки собирает один workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml). Он лежит в обеих ветках в одинаковом виде и всегда собирает обе по явным `ref` — не важно, push в какую ветку его запустил. Правите в одной ветке — перенесите во вторую.

Push в `main` или в `prototypes` пересобирает и публикует сайт целиком.

## Как пользоваться

- **Разработчику:** начинать с [02 — Функциональные требования](docs/02-functional-requirements.md) и [03 — MVP и роадмап](docs/03-mvp-and-roadmap.md). Область MVP — только то, что помечено этапом **MVP**.
- **Дизайнеру:** начинать с [01 — Обзор продукта](docs/01-product-overview.md) и [04 — Конкуренты](docs/04-competitors.md) (референс по дизайну — HWPO Training), затем открыть [прототип](https://serjnsk.github.io/trenergram/prototype/).
- Каждая функция имеет стабильный ID (например `CON-3`) — используйте его в задачах, макетах и обсуждениях.

## Локальная сборка документации

```bash
pip install "mkdocs-material==9.7.7"
mkdocs serve
```

Версия закреплена намеренно: MkDocs 2.0 ломает темы и плагины без пути миграции.
