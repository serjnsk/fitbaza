# 05 — Решения и открытые вопросы

Реестр продуктовых и технических решений, которые не выводятся из остальных документов, и вопросов, которые предстоит закрыть. У каждого пункта стабильный ID (OQ-N) — для ссылок из задач и обсуждений.

## Принятые решения

### OQ-1. Название продукта

На период разработки используется тестовое название **«fitbaza»**. Финальное название, домен и имена в App Store / Google Play утверждаются перед запуском — задача пре-лонч-чеклиста.

### OQ-2. Платформы тренера

Веб-версия конструктора входит в MVP: работа тренера по составлению программ почти всегда идёт с компьютера. Мобильные приложения — для всех ролей; телефон тренер использует в зале.

### OQ-3. Технологический стек

React Native + Expo (мобильные), React + Vite (веб-конструктор и админка), TypeScript-монорепо; оффлайн — PowerSync (self-hosted), SQLite ↔ PostgreSQL; backend — Node.js/NestJS, Redis, S3-совместимое хранилище; хостинг в РФ. Обоснование, альтернативы и обязательные спайки — в [06 — Технологический стек](06-tech-stack.md).

### OQ-4. Платёжный провайдер

**Т-Банк**: уже используется в других продуктах, есть опыт интеграции и действующие отношения с банком. Интеграция — этап 2 (модуль PAY).

### OQ-5. Комиссия App Store / Google Play

Подписка тренера на сервис (PAY-8) оплачивается только в веб-версии — платёж не попадает под комиссию сторов (15–30 %). Платежи клиентов тренеру (PAY-1…PAY-7) в MVP не входят; схема для них проектируется на этапе 2.

### OQ-6. Хранение и обработка видео

Видео храним у себя: удобного публичного видеохостинга нет — YouTube в РФ частично заблокирован (нужен VPN), Rutube — реклама и неудобный плеер. Схема — по [06 — Технологический стек](06-tech-stack.md): S3-совместимое хранилище в РФ + транскодинг (ffmpeg) + HLS.

### OQ-7. Персональные и медицинские данные

Юридическая схема работы с персональными и медицинскими данными согласована. Требования 152-ФЗ (локализация данных, согласия на обработку) учитываются при реализации профиля (PRO-3).

### OQ-9. Стартовая база упражнений

Контент базы приобретается **разовым выкупом датасета с самостоятельным хостингом**. Живой внешний API несовместим с оффлайн-архитектурой: упражнения должны лежать в нашем Postgres и синхронизироваться на устройства (NFR-3), поэтому «сервис с API» на практике означает импорт датасета к нам.

Требования к базе:

- покрытие: тренажёрный зал и кроссфит (EX-1);
- тренер привязывает к упражнениям свои видео, видимые только ему и его клиентам (EX-2);
- публичные видео для всех упражнений не обязательны — стартовая база может быть без видео.

Рынок поставщиков:

| Сервис | Что даёт | Модель | Вердикт |
|---|---|---|---|
| [EDB Exercise Intelligence (exercisedb.io)](https://exercisedb.io/pricing) | 1 394 упражнения, GIF в 4 разрешениях, 17 полей метаданных, связи «похожие / замены / прогрессии / регрессии», self-hosted | **Разовая коммерческая лицензия:** Mobile $299, Web $399, Cross-Platform $599 | ✅ **Основной кандидат.** Self-hosted — идеально под наш контур; связи «замены/прогрессии» напрямую питают CON-11 (альтернативные упражнения) |
| [WorkoutX](https://workoutxapp.com/) | 1 400+ упражнений, GIF, 6 языков (RU нет) | Только REST API по подписке ($9.99–24.99/мес), датасет не выкупается | ❌ Противоречит оффлайну — данные нельзя захостить у себя |
| [wger](https://wger.de) | Open source, self-hosted, частичная мультиязычность | Бесплатно (CC-лицензии) | Запасной вариант: слабее по полноте и качеству медиа |
| free-exercise-db (GitHub) | ~870 упражнений, JSON + фото | Public domain, бесплатно | Бесплатный fallback, если экономим на старте |
| [API Ninjas](https://api-ninjas.com/api/exercises) | Текст без медиа | API по подписке | ❌ Без медиа и без датасета |

План внедрения:

1. Перед покупкой — проверить бесплатный сэмпл EDB (30 упражнений): качество GIF, структура метаданных, покрытие кроссфит-движений.
2. Покупка **Cross-Platform ($599, разовая лицензия)** — у нас мобильные + веб. Импорт в наш Postgres, GIF — в наше S3-хранилище.
3. Русская локализация — своими силами: перевод названий и инструкций (AI-1 + вычитка); русского нет ни у одного поставщика.
4. Кроссфит-дополнение: ~80–120 специфических движений (ТА-вариации, гимнастика, double-unders, wall ball, эргометры) добавляются вручную — generic-базы покрывают их лишь частично.

### OQ-10. Текст ↔ структура в конструкторе

Канонический формат программы — структурированные данные (упражнения и показатели), а не текст; текстовый ввод — интерфейс поверх структуры с распознаванием на лету. Полная формулировка принципа — в [02 — Функциональные требования](02-functional-requirements.md) (раздел «Конструктор»); реализация — спайк №4 в [06 — Технологический стек](06-tech-stack.md).

## Открытые вопросы

### OQ-8. Модель монетизации платформы

Не зафиксирована; будет оформлена отдельным документом (`08-monetization.md`), после чего следствия разносятся в модуль PAY и тарифы. Контекст: TRNR берёт от 1000 ₽/мес в зависимости от числа клиентов; варианты — подписка тренера по числу клиентов, комиссия с платежей, гибрид.

### OQ-11. Юридическая схема выплат тренерам

Агентская схема или прямые платежи клиент → тренер (PAY-7). Определяется при проектировании этапа 2 вместе с моделью монетизации (OQ-8).

### OQ-12. Экономика видеохранилища

Расчёт стоимости хранения и трафика на одного тренера, лимиты в тарифах (модуль VID, этап 2). Связано с OQ-8.
